title: Data Products
description: Formats and contents of the EPIC pixel spectrograms, imaging sessions, FITS image cubes, daily digest and video stream.

Retaining every 80 ms all-sky image across the full station bandwidth would require approximately 110 TB per day (Reddy et al. 2024). The data products therefore combine two kinds of output:

- high-cadence, full-resolution data for a selected set of sources;
- lower-cadence data for the full sky.

| Product | Resolution | Coverage | Storage |
|---|---|---|---|
| Pixel spectrograms | 80 ms; 25 kHz; four polarization products | 5 × 5 pixels around each watched source | PostgreSQL, `epic_pixels` |
| Imaging sessions | One record per tuning | Metadata | PostgreSQL, `epic_img_metadata2` |
| Image cubes | 1.28 s; all channels; four products | Full sky | FITS and PNG files |
| Daily digest | 1.28 s | Stokes I and V spectra of watched sources | PostgreSQL, `epic_daily_digest` |
| Video | 80 ms (12.5 frames s⁻¹); one channel; Stokes I | Full sky | [EPIC TV](https://livetv.epic-astronomy.org) |

## Watch list

Pixel data are recorded only for sources on the watch list, which is maintained by the watchdog service. The list contains two kinds of entry:

- **Persistent entries**, such as the Sun, Jupiter, bright pulsars and the A-team sources.
- **Time-limited entries**, created in response to external alerts such as CHIME/FRB VOEvents.

Each entry records the event time, position, observing window, reason and, where applicable, the originating VOEvent. Sources below an elevation of 10° are not extracted.

## Pixel spectrograms (`epic_pixels`)

Each row contains one pixel of one source in one 83.6 ms image.

| Column | Type | Description |
|---|---|---|
| `img_time` | timestamp | Mid-point of the integration (UTC) |
| `chan0` | integer | First channel of the band; $\nu_0 = \texttt{chan0}\times 23.93$ kHz (196 MHz / 8192) |
| `source_name` | text | Watch-list identifier |
| `pixel_coord` | point | Pixel coordinates $(x, y)$ |
| `pix_offset` | point | Offset from the central pixel of the patch; $(0,0)$ denotes the central pixel |
| `pixel_lm` | point | Direction cosines $(l, m)$ of the pixel in the image frame |
| `source_pix` | point | Exact, fractional pixel position $(x, y)$ of the source when the image was made (from imager version 0.19; empty in earlier rows) |
| `pixel_values` | bytea | Spectra of the four polarization products |

The field `pixel_values` contains little-endian 32-bit floating-point values, ordered by channel, with the four products interleaved:

```text
[ XX*(ν₀), YY*(ν₀), Re XY*(ν₀), Im XY*(ν₀),  XX*(ν₁), YY*(ν₁), … ]   length 4 n_chan
```

A row may be decoded as follows:

```python
import numpy as np
v = np.frombuffer(row.pixel_values, dtype='<f4').reshape(n_chan, 4)
xx, yy, xy_re, xy_im = v.T
stokes_i = xx + yy                              # uncalibrated pseudo-Stokes I
freqs = (chan0 + 2 * np.arange(n_chan)) * 196e6 / 8192   # Hz; each stored channel sums two
```

The patch is centred on the pixel nearest the source and moves by one pixel each time the source crosses a pixel boundary, every few minutes (see [Imager Pipeline](/docs/lwa-sv-imager/pipeline)). The central pixel, `pix_offset = (0,0)`, therefore changes abruptly at each move. A continuous dynamic spectrum is obtained by interpolating the patch of each image at the exact position of the source, `source_pix`, relative to the central pixel `pixel_coord`. With a separable Lanczos-2 kernel this reads:

```python
import numpy as np

def lanczos2(t):
    t = np.asarray(t, float)
    return np.where(np.abs(t) < 2, np.sinc(t) * np.sinc(t / 2), 0.0)

# patch: [5, 5, n_chan] Stokes I of one image, indexed [dy + 2, dx + 2] by pix_offset
# dx, dy: source_pix minus pixel_coord of the central pixel, each within half a pixel
k = np.arange(-2, 3)
wx, wy = lanczos2(k - dx), lanczos2(k - dy)
w = np.outer(wy / wy.sum(), wx / wx.sum())
stokes_i_at_source = np.tensordot(w, patch, axes=([0, 1], [0, 1]))
```

The surrounding pixels of the patch provide a local reference. Interference and ionospheric effects tend to appear across the patch, whereas emission from an unresolved source is concentrated around its position.

The table accumulates of order $10^9$ rows per day. Each compute node stores the rows of its own sub-band, partitioned in time and retained for a finite period. Spectrograms are retrieved through the [Waterfalls](/waterfalls/spectrograms) application or its API, in intervals of up to 180 s.

## Imaging sessions (`epic_img_metadata2`)

An imaging session is a contiguous interval at a fixed tuning. A new session, with a new `session_id`, is opened whenever the station is retuned. Each session record contains:

- `session_start` and `session_end`
- `chan0`, `n_chan`, `n_pol` (four) and `chan_bw_hz`
- the integration time `int_time`
- the image size
- the patch size `npix_kernel`
- the git revision of the imager, `epic_version`
- the names of the watched sources

The Waterfalls application uses this table to enumerate the sessions available for a source within a given time range.

## Image cubes (FITS)

An accumulated image cube is written every `--nimg_accum` images (1.28 s at LWA-SV). The file format is as follows:

- **File name.** `EPIC_<unix_time>_<cfreq>MHz.fits`, accompanied by a `_QL.png` quick-look image.
- **Axes.** `(stokes, frequency, y, x)`. The four planes contain $XX^*$, $YY^*$, $\mathrm{Re}\,XY^*$ and $\mathrm{Im}\,XY^*$.
- **Projection.** `RA---SIN` / `DEC--SIN`, with the reference position at the zenith at the epoch of the image, in FK5 J2000.
- **Units.** `BUNIT = UNCALIB` (see [Calibration](/docs/theory/calibration)).
- **Further keywords.** Integration time, center frequency, grid size and grid sampling.

Each file is registered in the table `epic_files_metadata`, together with its imaging parameters.

## Daily digest (`epic_daily_digest`)

For each accumulated cube, two spectra are recorded for every watched source:

- **Stokes I:** the sum of $XX^* + YY^*$ over the source patch.
- **Stokes V:** a spectrum derived from $|\mathrm{Im}\,XY^*|$.

Both are tagged with the center frequency. The [Daily Digest](/waterfalls/spectrograms/dailydigest) view presents these spectra as day-long dynamic spectra, which serve as an index to intervals of activity in the 80 ms data.

## Video stream

The EPIC TV stream presents Stokes I of a single channel at 80 ms cadence (12.5 frames s⁻¹), with a perceptual color map, a horizon mask and a frequency and time annotation. Each frame is normalized independently, so the stream represents relative rather than absolute brightness. The most prominent features are:

- the Sun and the A-team sources traversing the sky;
- ionospheric scintillation;
- interference near the horizon.

During station health checks the stream displays a placeholder frame.
